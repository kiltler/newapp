# HTTP-сервис 1С «Checkins» для интеграции с NVR Monitor (модуль «Заселения»)

Этот файл — 1С-сторона интеграции: HTTP-сервис, который отдаёт панели свежие
заселения за период. Нужен там, где стандартный OData 1С не даёт фильтровать по
дате на больших базах (напр. «Ворон» — 160k документов `Document_Accommodation`).

App-сторона уже готова: у подключения 1С есть поле **«URL HTTP-сервиса»**
(`onec_connections.service_url`). Если оно задано — заселения берутся из этого
сервиса (`app/services/onec_sync.py::_fetch_from_service`), OData остаётся фолбэком.

---

## Контракт (что панель ждёт от сервиса)

Панель делает **GET** с Basic-авторизацией (логин/пароль пользователя 1С из карточки
подключения) и добавляет параметр `since` (наивное локальное время, ISO):

```
GET http://<хост>/<база>/hs/checkins/v1?since=2026-07-07T00:00:00
```

Ответ — JSON `{"items": [...]}` (или просто массив), каждый элемент:

| поле      | смысл                                   | тип                         |
|-----------|-----------------------------------------|-----------------------------|
| `ref`     | Ref_Key документа (GUID)                | строка                      |
| `checkin` | время заселения (метка на таймлайне)    | ISO `ГГГГ-ММ-ДДTЧЧ:ММ:СС`   |
| `date`    | дата документа (запасная метка)         | ISO или null                |
| `room`    | номер комнаты                           | строка или null             |
| `floor`   | этаж                                    | число или null              |
| `guest`   | ФИО гостя                               | строка или null             |

Время — **наивное локальное** время сервера 1С (пояс Хабаровска), без конверсии в
UTC (это принципиально, см. CLAUDE.md §6.2). Панель на своей стороне ещё раз режет
окно по `since`, так что лишние записи безвредны.

---

## Почему это НЕ сломает базу 1С

1. **Расширение конфигурации, а не основная конфигурация.** Типовая 1С:Отель
   остаётся на поддержке, обновления накатываются как обычно. Расширение можно
   выключить/удалить в любой момент — данные не трогаются.
2. **Только чтение.** Внутри — один SELECT-запрос. Ни записи, ни проведения
   документов: физически не может изменить учётные данные.
3. **Отдельный пользователь 1С** с минимальными правами: использование
   HTTP-сервисов + чтение `Accommodation` и номерного фонда. Даже при баге писать
   нечего.
4. **Сначала на копии базы.** Разворачиваешь на тестовой копии/бэкапе, проверяешь
   `?since=...`, и только потом на боевой.
5. Публикация HTTP-сервисов на IIS — это настройка веб-сервера, саму базу не меняет.

## Код модуля HTTP-сервиса `Checkins`

> Имена объекта/реквизитов зависят от редакции 1С:Отель — **проверь под свою базу**
> (в панели они тоже настраиваемые). Стандартные реквизиты даны для РУССКОЙ
> платформы (`Ссылка/Дата/Проведен/Наименование`); для англ. платформы замени на
> `Ref/Date/Posted/Description`. Прикладные (`CheckInDate/GuestFullName/Room/Floor`)
> — как в конфигурации.

```bsl
// HTTP-сервис "Checkins" (расширение конфигурации CheckinsAPI)
// Корневой URL: checkins | Шаблон URL: /v1 | Метод HTTP: GET → обработчик v1GET
// Публикация: http://<хост>/<база>/hs/checkins/v1?since=2026-07-07T00:00:00
// ВНИМАНИЕ: сервис ТОЛЬКО ЧИТАЕТ. Ничего не пишет и не проводит.

Функция v1GET(Запрос) Экспорт

	Граница = ГраницаИзПараметра(Запрос);

	Запрос1С = Новый Запрос;
	Запрос1С.УстановитьПараметр("Граница", Граница);
	Запрос1С.Текст =
	"ВЫБРАТЬ
	|	Док.Ссылка              КАК Ссылка,
	|	Док.Дата                КАК Дата,
	|	Док.CheckInDate         КАК ДатаЗаселения,
	|	Док.GuestFullName       КАК Гость,
	|	Док.Room.Наименование   КАК Номер,
	|	Док.Room.Floor          КАК Этаж
	|ИЗ
	|	Документ.Accommodation КАК Док
	|ГДЕ
	|	Док.Проведен
	|	И Док.CheckInDate >= &Граница
	|УПОРЯДОЧИТЬ ПО
	|	Док.CheckInDate";

	Выборка = Запрос1С.Выполнить().Выбрать();

	Массив = Новый Массив;
	Пока Выборка.Следующий() Цикл
		Стр = Новый Соответствие;
		Стр.Вставить("ref",     Строка(Выборка.Ссылка.УникальныйИдентификатор()));
		Стр.Вставить("checkin", ДатаВISO(Выборка.ДатаЗаселения));
		Стр.Вставить("date",    ДатаВISO(Выборка.Дата));
		Стр.Вставить("room",    ?(ЗначениеЗаполнено(Выборка.Номер), Строка(Выборка.Номер), Неопределено));
		Стр.Вставить("floor",   ЭтажКакЧисло(Выборка.Этаж));
		Стр.Вставить("guest",   ?(ЗначениеЗаполнено(Выборка.Гость), Строка(Выборка.Гость), Неопределено));
		Массив.Добавить(Стр);
	КонецЦикла;

	Тело = ВСтрокуJSON(Новый Структура("items", Массив));

	Ответ = Новый HTTPСервисОтвет(200);
	Ответ.Заголовки.Вставить("Content-Type", "application/json; charset=utf-8");
	Ответ.УстановитьТелоИзСтроки(Тело, КодировкаТекста.UTF8);
	Возврат Ответ;

КонецФункции

// since приходит как 2026-07-07T14:00:00 (наивное локальное). Пусто/битое → −5 суток.
Функция ГраницаИзПараметра(Запрос)
	Стр = Запрос.ПараметрыЗапроса.Получить("since");
	Если Стр = Неопределено ИЛИ ПустаяСтрока(Стр) Тогда
		Возврат НачалоДня(ТекущаяДата()) - 5*24*3600;
	КонецЕсли;
	Цифры = "";
	Для Инд = 1 По СтрДлина(Стр) Цикл
		С = Сред(Стр, Инд, 1);
		Если С >= "0" И С <= "9" Тогда
			Цифры = Цифры + С;
		КонецЕсли;
	КонецЦикла;
	Попытка
		Возврат Дата(Лев(Цифры, 14)); // ожидаем ГГГГММДДЧЧММСС
	Исключение
		Возврат НачалоДня(ТекущаяДата()) - 5*24*3600;
	КонецПопытки;
КонецФункции

Функция ДатаВISO(Знач Д)
	Если НЕ ЗначениеЗаполнено(Д) Тогда
		Возврат Неопределено;
	КонецЕсли;
	Возврат Формат(Д, "ДФ=гггг-ММ-дд") + "T" + Формат(Д, "ДФ=ЧЧ:мм:сс");
КонецФункции

// «1»,«2» → число; «цоколь»/«мансарда»/пусто → Неопределено (в JSON null)
Функция ЭтажКакЧисло(Знач Значение)
	Если ТипЗнч(Значение) = Тип("Число") Тогда
		Возврат Значение;
	КонецЕсли;
	Стр = СокрЛП(Строка(Значение));
	Если ПустаяСтрока(Стр) Тогда
		Возврат Неопределено;
	КонецЕсли;
	Попытка
		Возврат Число(Стр);
	Исключение
		Возврат Неопределено;
	КонецПопытки;
КонецФункции

Функция ВСтрокуJSON(Знач Данные)
	Запись = Новый ЗаписьJSON;
	Запись.УстановитьСтроку(Новый ПараметрыЗаписиJSON(ПереносСтрокJSON.Нет));
	ЗаписатьJSON(Запись, Данные);
	Возврат Запись.Закрыть();
КонецФункции
```

### Примечание по фильтру даты
Фильтр `Док.CheckInDate >= &Граница` пропустит документы с ПУСТЫМ `CheckInDate`.
Если такие есть — добавь запасное условие по дате документа:

```
|ГДЕ
|	Док.Проведен
|	И (Док.CheckInDate >= &Граница
|	   ИЛИ (НЕ Док.CheckInDate > ДАТАВРЕМЯ(1,1,1) И Док.Дата >= &Граница))
```

## Пошаговое внедрение

1. **Конфигуратор** → открыть базу (сначала КОПИЮ) → *Конфигурация → Расширения
   конфигурации* → добавить расширение: имя `CheckinsAPI`, назначение
   «Дополнение», префикс например `чк_`.
2. В расширении добавить объект **HTTP-сервис**: Имя = `Checkins`, Корневой URL =
   `checkins`. Внутри добавить **Шаблон URL** `/v1`, в нём **Метод HTTP** `GET`,
   обработчик `v1GET`. Вставить код модуля (выше).
3. Проверить имена объекта/реквизитов под свою редакцию 1С:Отель.
4. Обновить конфигурацию базы (F7), включить расширение.
5. **Опубликовать HTTP-сервисы** в существующей публикации (напр. `voronhot`) на
   IIS: *Администрирование → Публикация на веб-сервере → вкладка HTTP-сервисы →*
   отметить `Checkins` → Опубликовать/Перепубликовать. Перезапустить пул IIS.
6. Права пользователю 1С: использование HTTP-сервисов + чтение `Accommodation` и
   номерного фонда (комнат).
7. **Проверка** (браузер/curl, с basic-авторизацией пользователя 1С):
   ```
   http://192.168.1.2/voronhot/hs/checkins/v1?since=2026-07-07T00:00:00
   ```
   Ожидаем `{"items":[ {ref,checkin,date,room,floor,guest}, ... ]}`.
8. **В панели**: Заселения → Настройки → 1С → «Ворон» → поле «URL HTTP-сервиса» =
   `http://192.168.1.2/voronhot/hs/checkins/v1`, логин/пароль пользователя 1С →
   Сохранить → «Проверить связь» (ждём `mode: service, count: N`) → «Синхронизировать».
9. Для 2-й и 3-й гостиниц — то же расширение в их базах, в панели свой URL
   `.../hs/checkins/v1`.

### Ожидаемый лог успеха (в панели)
```
1С HTTP-сервис GET http://192.168.1.2/voronhot/hs/checkins/v1?since=...
1С HTTP-сервис: HTTP 200
1С HTTP-сервис: получено N заселений в окне
```
