# HTTP-сервис 1С «Checkins» для интеграции с NVR Monitor (модуль «Заселения»)

1С-сторона интеграции: HTTP-сервис, отдающий панели свежие заселения за период.
Нужен там, где стандартный OData 1С не фильтрует по дате на больших базах
(«Ворон» — ~160k документов).

Целевая конфигурация: **1С:Отель ред. 9.2, обычные формы, платформа 8.3.25**,
толстый клиент, база `voronhot` опубликована на IIS.

App-сторона уже готова: у подключения 1С есть поле **«URL HTTP-сервиса»**
(`onec_connections.service_url`). Если задано — заселения берутся из сервиса
(`app/services/onec_sync.py::_fetch_from_service`), OData остаётся фолбэком.

---

## Контракт (что панель ждёт)

**GET** с Basic-авторизацией (логин/пароль пользователя 1С из карточки подключения),
параметр `since` — наивное локальное время (пояс сервера 1С), ISO:

```
GET http://<хост>/voronhot/hs/checkins/v1?since=2026-07-07T00:00:00
→ {"items": [ {ref, checkin, date, room, floor, guest}, ... ]}
```

| поле      | из 1С                          | тип                        |
|-----------|--------------------------------|----------------------------|
| `ref`     | `Ссылка` (GUID документа)      | строка                     |
| `checkin` | `CheckInDate` (метка таймлайна)| ISO `ГГГГ-ММ-ДДTЧЧ:ММ:СС`  |
| `date`    | `Дата` документа (запас)       | ISO / null                 |
| `room`    | номер комнаты (через `Комната`)| строка / null              |
| `floor`   | этаж комнаты                   | число / null               |
| `guest`   | `GuestFullName`                | строка / null              |

Время — наивное локальное (без UTC, CLAUDE.md §6.2). Панель ещё раз режет окно по
`since`, лишние записи безвредны.

---

## Почему это НЕ сломает базу

1. **Расширение конфигурации, не основная конфигурация.** Типовая остаётся на
   поддержке, обновления не ломаются; расширение выключается/удаляется в один клик.
2. **Только чтение** — один SELECT. Ни записи, ни проведения документов.
3. **Отдельный пользователь 1С** с правами: HTTP-сервисы + чтение размещений и
   номерного фонда. Писать нечем даже при баге.
4. **Сначала на копии базы.**
5. Публикация на IIS меняет только веб-сервер (`default.vrd`), не базу.

> HTTP-сервисы работают на СЕРВЕРЕ и не требуют управляемых форм — в конфигурации
> на обычных формах (8.3.25) добавляются и публикуются штатно.

## Код модуля HTTP-сервиса `Checkins`

> ⚠️ **Сверь имена в конфигураторе своей базы!** Ниже — типовые для 1С:Отель 9.2,
> но реквизиты могли переименовать. Дерево: *Документы → Accommodation → Реквизиты*
> (есть ли `CheckInDate`, `GuestFullName`, `Комната`) и *Справочники → (номерной
> фонд) → Реквизиты* (как называется «этаж»: `Этаж`? и «номер»: `Наименование`/
> `Номер`?). Стандартные реквизиты на русской платформе: `Ссылка/Дата/Проведен`.

```bsl
// HTTP-сервис "Checkins" (расширение конфигурации CheckinsAPI)
// Корневой URL: checkins | Шаблон URL: /v1 | Метод HTTP: GET → обработчик v1GET
// Публикация: http://<хост>/voronhot/hs/checkins/v1?since=2026-07-07T00:00:00
// ВНИМАНИЕ: сервис ТОЛЬКО ЧИТАЕТ. Ничего не пишет и не проводит.

Функция v1GET(Запрос) Экспорт

	Граница = ГраницаИзПараметра(Запрос);

	Запрос1С = Новый Запрос;
	Запрос1С.УстановитьПараметр("Граница", Граница);
	Запрос1С.Текст =
	"ВЫБРАТЬ
	|	Док.Ссылка               КАК Ссылка,
	|	Док.Дата                 КАК ДатаДок,
	|	Док.CheckInDate          КАК ДатаЗаселения,
	|	Док.GuestFullName        КАК Гость,
	|	Док.Комната.Наименование КАК Номер,
	|	Док.Комната.Этаж         КАК Этаж
	|ИЗ
	|	Документ.Accommodation КАК Док
	|ГДЕ
	|	Док.Проведен
	|	И Док.CheckInDate >= &Граница
	|УПОРЯДОЧИТЬ ПО
	|	Док.CheckInDate";

	Выборка = Запрос1С.Выполнить().Выбрать();

	Массив = Новый Массив;
	Пока Выборка.Следующий() Цикл
		Стр = Новый Соответствие;
		Стр.Вставить("ref",     Строка(Выборка.Ссылка.УникальныйИдентификатор()));
		Стр.Вставить("checkin", ДатаВISO(Выборка.ДатаЗаселения));
		Стр.Вставить("date",    ДатаВISO(Выборка.ДатаДок));
		Стр.Вставить("room",    ?(ЗначениеЗаполнено(Выборка.Номер), Строка(Выборка.Номер), Неопределено));
		Стр.Вставить("floor",   ЭтажКакЧисло(Выборка.Этаж));
		Стр.Вставить("guest",   ?(ЗначениеЗаполнено(Выборка.Гость), Строка(Выборка.Гость), Неопределено));
		Массив.Добавить(Стр);
	КонецЦикла;

	Тело = ВСтрокуJSON(Новый Структура("items", Массив));

	Ответ = Новый HTTPСервисОтвет(200);
	Ответ.Заголовки.Вставить("Content-Type", "application/json; charset=utf-8");
	Ответ.УстановитьТелоИзСтроки(Тело, КодировкаТекста.UTF8);
	Возврат Ответ;

КонецФункции

// since приходит как 2026-07-07T14:00:00 (наивное локальное). Пусто/битое → −5 суток.
Функция ГраницаИзПараметра(Запрос)
	Стр = Запрос.ПараметрыЗапроса.Получить("since");
	Если Стр = Неопределено ИЛИ ПустаяСтрока(Стр) Тогда
		Возврат НачалоДня(ТекущаяДата()) - 5*24*3600;
	КонецЕсли;
	Цифры = "";
	Для Инд = 1 По СтрДлина(Стр) Цикл
		С = Сред(Стр, Инд, 1);
		Если С >= "0" И С <= "9" Тогда
			Цифры = Цифры + С;
		КонецЕсли;
	КонецЦикла;
	Попытка
		Возврат Дата(Лев(Цифры, 14)); // ожидаем ГГГГММДДЧЧММСС
	Исключение
		Возврат НачалоДня(ТекущаяДата()) - 5*24*3600;
	КонецПопытки;
КонецФункции

Функция ДатаВISO(Знач Д)
	Если НЕ ЗначениеЗаполнено(Д) Тогда
		Возврат Неопределено;
	КонецЕсли;
	Возврат Формат(Д, "ДФ=гггг-ММ-дд") + "T" + Формат(Д, "ДФ=ЧЧ:мм:сс");
КонецФункции

// «1»,«2» → число; «цоколь»/«мансарда»/пусто → Неопределено (в JSON null)
Функция ЭтажКакЧисло(Знач Значение)
	Если ТипЗнч(Значение) = Тип("Число") Тогда
		Возврат Значение;
	КонецЕсли;
	Стр = СокрЛП(Строка(Значение));
	Если ПустаяСтрока(Стр) Тогда
		Возврат Неопределено;
	КонецЕсли;
	Попытка
		Возврат Число(Стр);
	Исключение
		Возврат Неопределено;
	КонецПопытки;
КонецФункции

Функция ВСтрокуJSON(Знач Данные)
	Запись = Новый ЗаписьJSON;
	Запись.УстановитьСтроку(Новый ПараметрыЗаписиJSON(ПереносСтрокJSON.Нет));
	ЗаписатьJSON(Запись, Данные);
	Возврат Запись.Закрыть();
КонецФункции
```

### Если у части документов пустой `CheckInDate`
Фильтр по `CheckInDate` их пропустит. Тогда добавь запас по дате документа:
```
|ГДЕ
|	Док.Проведен
|	И (Док.CheckInDate >= &Граница
|	   ИЛИ (НЕ Док.CheckInDate > ДАТАВРЕМЯ(1,1,1) И Док.Дата >= &Граница))
```

## Пошагово в конфигураторе (толстый клиент)

1. Открыть базу (сначала **копию**). *Конфигурация → Открыть конфигурацию.*
2. *Конфигурация → Расширения конфигурации* → кнопка «+» → имя `CheckinsAPI`,
   синоним любой, назначение **«Дополнение»**, префикс например `чк_`. Открыть
   конфигурацию расширения.
3. В дереве расширения ПКМ на ветке **HTTP-сервисы → Добавить**:
   - Имя: `Checkins`
   - Корневой URL: `checkins`
4. У сервиса ПКМ **Шаблоны URL → Добавить**: Имя `v1`, **Шаблон**: `/v1`.
5. У шаблона `v1` ПКМ **Методы → Добавить**: Имя `v1GET`, **HTTP-метод**: `GET`,
   **Обработчик**: `v1GET`.
6. Открыть **Модуль HTTP-сервиса** (ПКМ на `Checkins` → «Открыть модуль») и
   вставить весь код выше. Сохранить.
7. *Конфигурация → Обновить конфигурацию базы данных* (F7). Расширение включить
   (галка «Активно» в списке расширений).
8. **Публикация на IIS** (публикация `voronhot` уже есть):
   *Администрирование → Публикация на веб-сервере…* → выбрать существующую
   публикацию `voronhot` → вкладка **HTTP-сервисы** → включить «Публиковать
   HTTP-сервисы по умолчанию» **или** отметить конкретно `Checkins` → **Опубликовать**
   (перезапись `default.vrd`). Затем перезапустить пул приложения IIS
   (или `iisreset`).
9. Пользователю 1С, под которым ходит панель, дать роль: право **«Использование
   HTTP-сервисов»** + чтение размещений и номерного фонда.
10. **Проверка** (браузер, с basic-авторизацией пользователя 1С):
    ```
    http://<хост>/voronhot/hs/checkins/v1?since=2026-07-07T00:00:00
    ```
    Ожидаем `{"items":[ {ref,checkin,date,room,floor,guest}, ... ]}`.

## Переключение панели (нашего OneCBackend) на сервис

Переключение уже поддержано кодом — **отдельная сборка не нужна**, достаточно
заполнить URL в UI:

- `OneCBackend.fetch_checkins()` при непустом `service_url` вызывает
  `_fetch_from_service()` (GET `service_url?since=…`), OData не трогается.
- Ответ приводится к внутренней форме, `extract_room_floor()` берёт номер/этаж
  (этаж принимается числом, float и строкой; «цоколь»/«мансарда» → null).
- «Проверить связь» в режиме сервиса возвращает `mode: service, count: N` и
  `room_expanded {number, floor}` — сразу видно, что комната/этаж распарсились.

Порядок:
1. Заселения → **Настройки → 1С → «Ворон»**.
2. Поле **«URL HTTP-сервиса 1С (приоритетно)»** =
   `http://<хост>/voronhot/hs/checkins/v1`
3. Логин/пароль пользователя 1С (тот, кому дали право на HTTP-сервисы).
4. **Сохранить** → **Проверить связь** — ждём `mode: service, count: N` и
   заполненный `room_expanded`.
5. **Синхронизировать**. В логе панели:
   ```
   1С HTTP-сервис GET http://<хост>/voronhot/hs/checkins/v1?since=...
   1С HTTP-сервис: HTTP 200
   1С HTTP-сервис: получено N заселений в окне
   ```
6. Для 2-й и 3-й гостиниц — то же расширение в их базах, в панели свой URL.

Откат: очистить поле «URL HTTP-сервиса» → панель вернётся на OData.
